## 首次使用审查：浏览器报告复算兼容修复

- 在本 Mac Chrome 导入参考值为 `1000000000000000000`、`1000000000000000128`、`1000000000000000256`，输出为 `0`、`1`、`2` 的合成 CSV，实际下载完整 JSON。按 README 执行 `--replay`，修复前退出码为 1，提示分析结果不一致；修复后对同一个未修改的文件复算、另存均成功，源文本 SHA-256 核对通过。
- 原因是浏览器把同一 binary64 数值从科学记数法改写为整数形式；Python 解析后的整数与原浮点数直接比较可能不等。修复只调整同版本报告的分析值比较，不更改计算、报告格式或应用版本。
- 新增 9 项回归先复现问题，再全部通过；覆盖大参考值、大输出、同值数字写法、一个可表示步长的改动、缺键/多键、列表缺项、错误类型及整数溢出。测试使用标准库，不要求 Node。
- 本机另运行受影响的 12 项既有 CLI 测试和 15 项 I/O 测试，27 项全部通过；本轮未重复无关的核心计算与 HTTP 检查。完整跨平台检查由该提交的 [GitHub Actions](https://github.com/bte808/sensor-calibration-lab/actions) 执行，以实际运行结论为准。
- Windows 启动脚本和说明做了只读核查，未发现新的启动缺陷；未进行 Windows 图形界面人工验证。复算路径示例本就要求替换实际下载路径，本轮未扩展启动功能。
- CSV 错误路径另确认两项未修限制：有效数据不足时只显示排除数量，缺少行号和原因；替换已载入数据时，过大或无效 UTF-8 文件会使旧数据仍能重新计算。后一项以浏览器事件的 Node VM 模拟复现，未改导入流程；处理办法是刷新页面后重新导入，README 已注明。
